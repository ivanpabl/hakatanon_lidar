Что на пути поезда и как далеко

Детектор препятствий для тоннелей метро. По облаку точек на каждом кадре он решает: стоп, внимание или свободно — и отображает расстояние.

    Посмотреть, как он решает Результаты испытаний

    Прокрутка — ход поезда. Впереди на пути человек.

    Кадр: 128 колец точек

    Десять раз за секунду лидар присылает облако точек. Точки ложатся кольцами на пол и стены: редко у полотна и сгущаясь у горизонта.

    Что в сыром кадре

    Строки точек у горизонта идут с шагом 0,125°. Многие точки пустые: луч не возвращается. Столбцы идут парами (два отражения одного залпа), и почти всегда они совпадают. В конце, после удаления нулей и дублей, облако уменьшается в несколько раз.

    Сначала найти свой путь

    Вблизи ось пути строится по рельсам, дальше — по стенам тоннеля вплоть до 150–200 м.

    Как находятся рельсы

    Детектор ищет пару выступов по высоте, расположенных в 1,45–1,75 м друг от друга, с серединой прямо под поездом. По рельсам ось строится примерно до 40 м, дальше рельсы теряются среди редких точек. Если ось не найдена, кадр получает метку «путь не определён», а не «свободно».

    Коридор, где не должно быть ничего

    Вдоль оси — зона проверки шириной 2 м и высотой до 3 м над рельсом. Точки, попавшие внутрь, собираются в объекты.

    Размеры и фильтры

    По 1 м в каждую сторону от оси, от 0,15 до 3 м над головкой рельса. Высота полотна оценивается по дальности, так что зона следует за уклоном. Кабели, контактный рельс и стена в кривой тянутся вдоль края коридора, в результате такие продольные конструкции отсеиваются.

    Одна точка ещё не тревога

    Издалека человек — лишь несколько точек. Детектор ведёт объект от кадра к кадру и копит свидетельства; пока их мало, объект остаётся кандидатом, а решение — «внимание».

    Как отсекается то, что едет с поездом

    Положение объекта предсказывается с учётом хода поезда: неподвижный объект приближается на пройденный путь. Отражение или блик, который держит дистанцию, пока поезд едет, стоп не получает.

    Стоп: объект подтверждён

    Свидетельств набралось достаточно — объект подтверждён. Всего решений четыре, и каждый кадр получает одно из них:

    Стоп
    Препятствие на пути и дистанция до него.
    Внимание
    Кандидат, который ещё не подтверждён.
    Свободно
    Путь чист; указано, докуда он проверен.
    Путь не определён
    Ось пути не найдена, и это не «свободно».

    Демо на записи

    Настоящая запись doubleT_obstacle: поезд стоит, у рельсов человек. Каждый кадр прошёл через детектор, рядом — его решение по текущему кадру и дистанция. Сцену можно вращать мышью, а камеру двигать клавишами WASD.

        Архитектура в ROS 2

        Ядро детекции — пакет Python без ROS. Вокруг него два узла: приём облака на C++ и детектор на Python. Всё собирается в один Docker-образ на ROS 2 Humble.

        Ядро core/tunnel_od
        Python и numpy, без ROS. Тот же код считает метрики офлайн и работает в узле.
        Пересчёт пути
        Ось пути уточняется на каждом кадре. В режиме refit_mode: async это делает отдельный процесс path_worker, и кадр его не ждёт.
        Параметры
        Все параметры — в config/detector.yaml. Каталог монтируется в контейнер, так что после правки пересобирать образ не нужно.

        Запуск

        Цепочка из задания: сборка образа, запуск узла, проигрывание записи, результат по каждому кадру. Зависимости ставятся при сборке, так что для запуска сеть не нужна.

        Docker и ROS 2 Humble

        docker compose build
# узел + ros2 bag play, итог в output/
BAG=/путь/к/записи docker compose up play
# то же по кругу + RViz в браузере, порт 6080
BAG=/путь/к/записи docker compose up demo
# только узлы: живой лидар или свой плеер
docker compose up detector
# тесты: gtest (C++) и pytest (узел)
docker compose run --rm test

        BAG — каталог записи ros2 bag с metadata.yaml (.db3 или .mcap). Для детерминированной оценки без потери кадров: REFIT_MODE=sync MAX_PENDING=100000 RATE=0.5.

        ТопикЧто внутри
        /tunnel_od/resultJSON на кадр: status (stop, caution, clear, unknown), distance_m, clear_to_m, objects, latency_ms
        /tunnel_od/markersось пути, коридор, объекты, текст решения для RViz
        /tunnel_od/input_diagnosticsпроверка входного потока по контракту

        Python 3.10+, видеокарта не нужна. Отчёт — папка output/report с файлами index.html и demo.html; они открываются двойным щелчком, сеть не нужна.

        Ядро на Python

        from tunnel_od import ObstacleDetector, parse_pointcloud2

det = ObstacleDetector()
x, y, z = parse_pointcloud2(msg.data, msg.point_step, msg.fields)
result = det.detect(x, y, z)
result["status"], result["distance_m"], result["clear_to_m"]

        Геометрический детектор препятствий по лидару, без обучения. Сцена в начале страницы синтетическая: лучи 128 каналов трассируются в модели тоннеля прямо в браузере, человек в ней условный. Результаты и демо — из настоящих записей.
