    Есть ли что-то на пути поезда — и на каком расстоянии

    Система обрабатывает поток облаков точек 128-канального лидара беспилотного поезда метро. Для каждого кадра она выдаёт решение «препятствие есть / нет», дистанцию до ближайшего препятствия и список найденных объектов. Подход геометрический, без обучения: детектор сам находит свой путь в тоннеле и проверяет пространство над ним.

    Как работает

    Два потока работы. Раз в кадр в отдельном процессе уточняется, где проходит свой путь. Каждый кадр проверяется пространство над этим путём, а найденное копится по кадрам с учётом движения поезда.

    1. Свой путь по рельсам.

      Пара рельсов с колеёй 1,45–1,75 м берётся рядом с лидаром — поезд стоит на своём пути — и прослеживается вперёд срез за срезом. Чужие пути на станциях и стрелках не цепляются.

    2. Дальше рельсов — по стенам.

      Рельсы видны до ~40 м, стены — до 115–160 м. Ось ведётся так, чтобы расстояние до стен сохранялось; препятствие на пути ось не сдвигает.

    3. Высота полотна.

      Уклон пути и наклон лидара дают до 1,3 м разницы высоты на 80 м. Дно лотка оценивается в каждом кадре, крупный объект не принимается за «поднявшийся пол».

    4. Скорость поезда по сцене.

      Развёртка тоннеля вдоль оси сравнивается с кадром 5 кадров назад. Ошибка около 2 %, одометрия не нужна.

    5. Зона и объекты.

      Точки над рельсами собираются в объекты. Длинные цепочки у края коридора — кабель, контактный рельс, край платформы — тревогу не поднимают.

    6. Накопление вместо «3 из 5».

      Неподвижный объект приближается ровно на путь поезда за кадр. Трек прогнозируется, вклад каждого кадра — точки к ожидаемому минимуму. Дальний объект из 1–2 точек подтверждается за ~5 кадров, шум — никогда.

    Архитектура в ROS 2

    Ядро детекции — пакет Python без ROS. Вокруг него два узла: приём облака на C++ и детектор на Python. Всё собирается в один Docker-образ на ROS 2 Humble.

    Ядро core/tunnel_od

    Python + numpy, без ROS. Тот же код считает метрики офлайн и работает в узле. Ставится pip install ./core.

    Задержка

    Пересчёт пути (~80 мс) вынесен в отдельный процесс и не держит кадр. Кадр 8 МБ при 10 Гц: —.

    Параметры

    Всё в config/detector.yaml, монтируется в контейнер — после правки пересобирать образ не нужно.

    Демонстрация

    3D-плеер показывает реальные кадры записей после детектора: облако, ось пути, коридор, найденные объекты, решение и дистанцию. Детектор идёт с первого кадра отрывка, как на поезде.

    Открыть 3D-плеер

    Качество

    Главная метрика — на какой дальности неподвижный объект на пути впервые подтверждён, когда поезд к нему едет. Разметки реальных препятствий почти нет, поэтому объект вставляется в реальные кадры лучами настоящего датчика, с тенью. Ложные тревоги считаются на записях без препятствий.

    Что не вошло и почему

    • Нейросети. Нет разметки и GPU на стенде, а проверка — на других тоннелях. По той же причине не строится карта по прошлым проездам.
    • Сравнение с фоном тоннеля (method: background). Реализовано, на базовой версии давало меньше тревог внутри известной оси, но с вариантом P не сравнивалось.
    • Низкие предметы ниже 0,15 м над рельсом: шум у полотна больше 8 см в 4–18 % ячеек пустых записей.

    Известные ограничения

    • Кривые: дальше 60–120 м путь закрыт внутренней стеной, объект физически не виден.
    • Край габарита: объекты в 1,0–1,35 м от оси не видны; вдали — дальше 0,7 м.
    • Длинные объекты вдоль пути в дальней зоне (состав) отсеиваются как конструкции.
    • Малые выборки: 6 окон подъезда и ~24 мин записей; синтетика ставится на ось, найденную самим детектором.

    Запуск

    Цепочка из задания: docker build → docker run → ros2 bag play → результат. Все зависимости ставятся при сборке, при запуске сеть не нужна.

    Docker + ROS 2 Humble

    # собрать образ ./run.sh build # узел + ros2 bag play в одном контейнере ./run.sh play /путь/к/записи # только узел: для своего плеера или лидара ./run.sh detector topic:=/lidar_points # RViz на машине с графикой rviz2 -d ros2_ws/src/tunnel_od_detector/rviz/tunnel_od.rviz

    Результат каждого кадра — в /tunnel_od/result и runs/docker/<запись>_result.jsonl, итог и задержка — в _stats.json.

    Метрики и этот сайт без ROS

    # всё: тесты, метрики, дашборд, плеер (Windows: run_all.bat) python tools/run_all.py --jobs 2 # проверка окружения за пару минут python tools/run_all.py --quick # собрать сайт из results/ в site/ python tools/site.py

    Нужны Python 3.10+, pip install -e ./core[tools] и записи в data/. Видеокарта не нужна.
