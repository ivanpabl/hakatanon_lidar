## 2. Выход детектора: `status`, уровни объектов, `clear_to_m`

### 2.1 Уровень объекта

Новые поля объекта: `level` (`'stop'` | `'caution'` | `None`) и `reason` (строка или `None`).

| `level` | `reason` | Условие |
|---|---|---|
| `stop` | `in_gauge` | подтверждён, в пределах оси, не `ego_carried` |
| `caution` | `beyond_path` | подтверждён, за концом известной оси |
| `caution` | `ego_carried` | подтверждён, ЭГО-тест: едет вместе с поездом (раздел 4) |
| `caution` | `pending` | не подтверждён, трек ≥ 2 кадров и счёт ≥ 0,5·`evidence_threshold` |
| `None` | `None` | `too_small` без трека в `pending`, `edge_line`, одиночные кадры |

Если причин несколько, `reason` берётся первой по порядку строк таблицы. Объекты, удержанные `alarm_hold` (`held=True`), наследуют `level` и `reason` из последнего кадра, где их трек был виден.

### 2.2 Решение по кадру

- `status` по приоритету:
  1. `'stop'` — есть объект `stop`;
  2. `'unknown'` — нет оси пути (`path_available == False`): габарит проверить нельзя;
  3. `'caution'` — есть объект `caution`;
  4. `'clear'`.
- `obstacle = (status == 'stop')`. Узел, `alarms.py`, дашборд и демо, которые читают `obstacle`, работают без правок.
- `distance_m` — до ближайшего объекта `stop` (как сейчас до подтверждённого). Новое поле `caution_distance_m` — до ближайшего `caution` или `None`.

`unknown` — не тревога, но и не «свободно». Система безопасности не должна говорить «путь свободен», когда не видит путь. На скрытых данных (новые тоннели, гермозатворы, стрелки) именно здесь ось теряется. Доля кадров `unknown` показывается в каждом замере.

### 2.3 `sight_m` и `clear_to_m`

- `sight_m` — докуда путь виден: минимум из
  1. `path_range_m`;
  2. дальности прямой видимости на кривой `sqrt(8·R·c)`, `c = 1,5 м`; `R = 1/|κ|`, κ — вторая производная аппроксимации оси `cl(fwd)` на 40–120 м; при `|κ| < 1/5000` ограничения нет;
  3. 200 м — паспортный предел Pandar128 при отражении 10 %.
- `clear_to_m = min(sight_m, дистанция до ближайшего объекта stop или caution)` — докуда габарит проверен свободным.
- Без оси оба равны 0.

`sight_m` нужен для отчёта «обнаружили на X м при видимости Y м» (Q&A 4.10).

### 2.4 Где живёт

Новый модуль `core/tunnel_od/detection/decision.py`, чистые функции без состояния:

```python
def object_level(obj, *, in_path: bool, pending_score: float) -> tuple[str | None, str | None]
def decide(objects, *, path_available, path_range, curvature, sight_c=1.5, range_cap=200.0) -> dict
    # -> {'status', 'distance_m', 'caution_distance_m', 'sight_m', 'clear_to_m'}; level/reason пишутся в objects
```

`check_frame` вызывает `decide` вместо сегодняшнего вычисления `confirmed`. Кривизну оси считает `check_frame` по `_fit_fwd`/`_fitted_cl` и передаёт числом.

### 2.5 Отображение

- **Узел:** JSON — всё из `detect()` плюс новые поля. Маркеры RViz окрашены по `level`: красный `stop`, жёлтый `caution`, серый `None`. Текст: «СТОП 56 м» / «ВНИМАНИЕ 80 м» / «СВОБОДНО до 143 м» / «ПУТЬ НЕ ОПРЕДЕЛЁН».
- **`alarms.py`:** в покадровый CSV добавляются колонки `status`, `caution`, `sight_m`, `clear_to_m`, `travel_m`. Рядом пишется `runs/alarms_<tag>_objects.jsonl`: на каждый кадр объекты уровней `stop` и `caution` (кадр, `track_id`, `distance_m`, `lateral_m`, `height_m`, `low_m`, `n_points`, `level`, `reason`, `ego_slope`).
- **Дашборд и демо:** цвет объекта по `level`, строка решения со `status` и `clear_to_m`. Больше ничего в них не меняем.

## 3. Зона по габариту организаторов

Параметры зоны подбираются по бэгу организаторов (раздел 5), а не по выводам TunnelGuard. Новой модели зоны не вводим: меняются только значения существующих параметров `ObstacleDetector`.

### 3.1 Сетка вариантов

| Параметр | Сейчас | Варианты |
|---|---|---|
| `half_width` | 1,0 м | 1,0; 1,15 |
| `h_top` | 2,0 м | 2,0; 2,5; 3,0 |
| `far_top` | 1,5 м | 1,5; `h_top` |

`far_half_width` (0,7 м) и начало дальней зоны не трогаем: ступенька дальней зоны дала падение ложных тревог с 9,7 до 2,4 % (вариант L→P в `PLAN.md`).

Каждый вариант — одна строка `research/compare.sh`. Прогоняются только комбинации, которые может изменить ответ по объектам: сначала `half_width` при текущих высотах, затем `h_top` и `far_top` при выбранной ширине.

### 3.2 Правило выбора

1. Отбрасываем варианты, где СТОП получает объект 5, 7 или 8.
2. Среди оставшихся берём тот, где больше объектов 1, 2, 3, 4, 6, 9, 10 дают СТОП.
3. При равенстве — меньше кадров СТОП на 5 пустых записях и `new_data`.
4. **Исключение из критерия 8.1.2:** выбранный вариант может поднять долю кадров СТОП не больше чем на 0,5 п.п. на каждом наборе. Габарит задают организаторы, и за объекты у края они будут спрашивать. Если рост больше — остаёмся на текущих значениях, расхождение с габаритом организаторов описываем в README.

### 3.3 Объекты ниже полотна

Генератор может ставить объекты ниже оценённого полотна (1.3). Зону под это не расширяем: точки ниже полотна у нас — шум остатка (`research/floor_residual.py`). На этапе 0 для каждого объекта пишем `low_m` и высоту полотна на его дистанции. Если объект пропущен из-за этого, пишем в README как ограничение, с номером объекта.

## 4. ЭГО-тест в `EvidenceTracker`

### 4.1 Проблема

`EvidenceTracker.update` прогнозирует трек на `distance − displacement`, но после сопоставления записывает в трек наблюдённую дистанцию (`tracking.py`, `tr['distance_m'] = d`). Артефакт на постоянной дистанции промахивается каждый кадр ровно на `displacement` и проходит строб `gate_fwd + gate_rel·d` (1,5 м на 25 м), пока скорость меньше ~15 м/с. Так он копит свидетельство до тревоги.

### 4.2 Изменения

- `EvidenceTracker.update(objects, displacement=None, expected=None, travel=None)`. `travel` — накопленный пробег `ObstacleDetector._travel`.
- При сопоставлении трек дописывает пару `(travel, distance_m)` в `tr['obs']`, хранятся последние 20.
- Тест, когда в `obs` ≥ 4 пар и `max(travel) − min(travel) ≥ ego_min_travel`:
  - `slope = median((d_j − d_i) / (t_j − t_i))` по парам `i < j` с `|t_j − t_i| > 0,5 м` (Тейл–Сен), нужно ≥ 3 таких пары;
  - `ego_carried = slope > ego_max_slope`.
- Пока данных недостаточно, `ego_carried = False`.
- В объект пишутся `ego_slope` (или `None`) и `ego_carried`.
- `travel is None` или пробег не растёт (одометрия не оценилась, поезд стоит) — тест решения не выносит.

### 4.3 Параметры `ObstacleDetector`

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `ego_check` | `False` до приёмки | включить ЭГО-тест (только `tracker='evidence'`) |
| `ego_min_travel` | 4,0 м | минимальный пробег для решения |
| `ego_max_slope` | −0,35 | наклон выше — «едет с поездом» |

### 4.4 Главный риск и условие включения

В бэге организаторов кадры идут с промежутками до 0,8 с, объекты «замирают». Синтетический объект, который держит дистанцию, пока сцена едет, получит наклон около 0 и будет понижен до ВНИМАНИЕ. Это прямой пропуск на данных жюри.

`ego_check = True` включается, только если:
- на бэге организаторов ни один объект не потерял СТОП и дистанция первого СТОП не ухудшилась больше чем на 10 м;
- выполнены остальные жёсткие критерии 8.1.

Иначе флаг остаётся выключенным, в `PLAN.md` пишутся цифры и причина.

### 4.5 Известное ограничение

Поезд впереди, идущий в ту же сторону с той же скоростью, или человек, уходящий от поезда, дадут наклон около 0 и ВНИМАНИЕ вместо СТОП. Если объект начнёт приближаться, наклон вернётся к −1 и СТОП восстановится.

6. **Промежутки между кадрами.** `EgoMotion` сравнивает кадр с кадром на `LAG = 5` раньше и ищет сдвиг в окне `max_shift = 22,5 м` (`ego_motion.py:34`). При промежутках до 0,8 с поезд за это время проходит до 48 м. На этапе 0 сверяем пробег по одометрии с ожидаемым: ~100 м между соседними объектами. Если сдвиг выходит за окно, `update` возвращает `displacement = None` и не угадывает. Трекер при `None` уже расширяет строб на 2,5 м + 0,03·d (`tracking.py:84,94`).

### 5.2 Оценка (`tools/eval_fake_obj.py`)

- **Эталон `data/cloud_with_fake_obj/objects.yaml`**, строится один раз на этапе 0:
  1. прогон текущего детектора с записью всех объектов любого уровня в координате `X = travel_m + distance_m`;
  2. группы по `X` сопоставляются по порядку с объектами 1–10 из #437 (шаг ~100 м);
  3. каждая группа проверяется глазами (`research/show_frame.py`); объекты, которые детектор не увидел вовсе, ищутся глазами по ожидаемому `X`;
  4. в файл записываются номер, описание, ожидаемый уровень, окно `X ± 5 м`, смещение от оси, `low_m` и высота полотна.
- **Ожидаемый уровень:** СТОП — объекты 1, 2, 3, 4, 6, 9, 10; не СТОП — 5, 7, 8.
- **Метрики по объекту:** дистанция первого СТОП, `sight_m` в этом кадре, доля кадров СТОП после первого, итоговый уровень, `reason`.
- **Ложные СТОП:** кадры СТОП, объекты которых не попали ни в одно окно.
- **Выход:** `runs/fake_obj_<tag>.csv` и строка сводки: N из 7 объектов «в габарите» со СТОП, СТОП на 5/7/8 да/нет, ложные кадры.

### 5.3 Саморазметка проездом (`tools/selflabel.py`)

Нужна для одного утверждения в README и презентации: «N из M эпизодов СТОП на `new_data` доказанно ложные, остальные не разрешены». В подбор параметров не входит.

- **Вход:** покадровый CSV `alarms.py` (с `travel_m`) и `runs/alarms_<tag>_objects.jsonl`.
- **Эпизод:** кадры СТОП одного `track_id`; разрыв ≤ 5 кадров эпизод не рвёт. `X = travel_m + distance_m` на первом кадре эпизода.
- **Сегменты одометрии:** новый сегмент начинается, если `displacement_m` был `None` дольше 1 с. Эпизод размечается пробегом только своего сегмента.
- **Метка:** `false_proven`, если в том же сегменте позже `travel_m ≥ X + 3 + 0,02·distance_m`; иначе `unresolved`.
- **Санитарная проверка:** суммарный пробег `new_data` печатается; если он вне 10–16 км (ориентир TunnelGuard — 13,0 км), сводка помечается как ненадёжная.
- **Выход:** `runs/selflabel_<tag>.csv` (строка на эпизод) и сводка в stdout: число эпизодов по меткам, распределение по дистанции и `reason`.

### 5.4 Сводный прогон

`research/compare.sh <tag> '<json>'` дополнительно запускает `eval_fake_obj.py` и `selflabel.py`. Один вариант детектора — одна команда — одна строка таблицы:
- объекты организаторов: N из 7, СТОП на 5/7/8, первые СТОП;
- % кадров СТОП, ВНИМАНИЕ, `unknown`: 5 пустых записей, вся `new_data`;
- человек со 170 м, куб 0,4 м (`eval_approach.py`);
- `doubleT_obstacle`: дистанция первого СТОП на объекте 56 м.

## 8. Приёмка

Изменение этапов 2–3 включается по умолчанию, только если выполнены все жёсткие критерии относительно замера базы этапа 1.

### 8.1 Жёсткие

1. **Бэг организаторов:** ни один объект, дававший СТОП в базе, его не потерял; дистанция первого СТОП по каждому такому объекту не хуже базы минус 10 м; СТОП на объектах 5, 7, 8 не появился.
2. **Ложные СТОП:** доля кадров СТОП не больше базы на 5 пустых записях и на всей `new_data`. Для зоны — исключение 3.2.4 (+0,5 п.п.).
3. **ВНИМАНИЕ:** доля кадров ВНИМАНИЕ не больше базы плюс 5 п.п. на тех же наборах.
4. **Дальность:** человек при подъезде со 170 м (`eval_approach.py`) — медиана дальности первого СТОП ≥ 150 м; куб 0,4 м — не меньше базы минус 10 м.
5. **`doubleT_obstacle`:** первый СТОП на объекте 56 м не позже, чем в базе.
6. **Сборка и запуск:** e2e в Docker (`./run.sh play`) — обработано 100 % принятых кадров 8 МБ, задержка p95 < 100 мс; все pytest проходят, включая новые тесты раздела 9.

### 8.2 Целевые (не блокируют)

- бэг организаторов: СТОП на 7 из 7 объектов «в габарите», нет СТОП на 5, 7, 8, ноль ложных СТОП-кадров вне окон объектов;
- вся `new_data`: ≤ 1 % кадров СТОП;
- доля `unknown` на `new_data` ≤ 2 % кадров.

### 8.3 Разовые проверки

- Посмотреть глазами, что стоит на 56 м в `doubleT_obstacle`: человек A из разбора TunnelGuard (60 кадров в габарите) или неподвижный предмет. Вывод — в README.

## 9. Тесты (`tests/test_core.py`)

- `decide`:
  - приоритет `stop` > `unknown` > `caution` > `clear`;
  - `obstacle == (status == 'stop')`;
  - `sight_m`: без оси — 0; прямая — `min(path_range, 200)`; кривая R = 300 м — `sqrt(8·300·1,5) ≈ 60 м`;
  - `clear_to_m`: объект ближе `sight_m` — его дистанция.
- ЭГО-тест: постоянная дистанция при `displacement` 1,2 м → `ego_carried`; приближение со скоростью поезда → нет; стоящий поезд → нет решения; `travel=None` → нет решения.
- `parse_pointcloud2`: 26-байтное упорядоченное облако — без изменений; 16-байтное неупорядоченное с дублями — дубли сняты.
- Повтор кадра: побитово тот же кадр → прошлый результат с `repeated: true`, детектор не вызывается.
- `EgoMotion` (если делается 5.1.6): промежуток, выводящий сдвиг за окно, → `displacement = None`.
