# Dashboard для защиты

Откройте `gui/dashboard.html` двойным щелчком. Рядом должны лежать `gui/demo.html` (главная встраивает его как сцену) и `gui/landing.html` (ссылка «О решении»). Все три страницы работают без сети и сервера — переносите их вместе.

Маршрут между страницами: `landing.html` → «Результаты испытаний» → `dashboard.html` → «Полный плеер» → `demo.html`; из боковой панели дашборда есть обратные ссылки на лендинг и плеер. `tools/run_all.py` кладёт в `results/` все три файла (`landing.html`, `metrics.html`, `demo.html`) и переход `dashboard.html` → `metrics.html`, чтобы ссылки работали и там.

## Что показывает первый экран

Дашборд и лендинг считают разные наборы: на лендинге три числа из README, в дашборде — измерения из `runs/`/`reference/`. Не смешивайте их.

Раздел «Результаты испытаний» построен по рангу важности:

| Ранг | Метрика | Почему здесь |
| --- | --- | --- |
| 1 | **Дальность первого СТОП**, м | главный результат: на сколько раньше поезд узнаёт о препятствии |
| 1 | **Объекты в габарите**, N из 7 | единственная внешняя разметка — эталон организаторов |
| 2 | **Полная задержка p95**, мс | ограничение реального времени, бюджет 100 мс |
| 2 | **Ложные СТОП**, % | главное нерешённое место |
| 3 | технические показатели | дедлайн, ошибка дистанции, удержание СТОП, ось пути, СТОП вне габарита |

Критическая оговорка стоит внутри плитки своей метрики; всё остальное — во втором уровне (`details`) и в разделах «Границы решения», «Источники чисел», «Реестр доказательств». Ни один отрицательный результат не убран.

Палитра функциональная: нейтральная основа, один акцент (навигация, ссылки, итоговая версия на графиках), красный только для решения СТОП и ложных тревог, янтарный только для оговорки рядом с числом.

## Маршрут показа

1. **Демонстрация**: автоматически повторяется фрагмент `doubleT_obstacle`, кадры 10–68, с приближением камеры к человеку у рельсов. Это запись, не онлайн-поток. Камера наводится на подтверждённый объект кадра, его габарит обведён рамкой и подписан дистанцией, а решение детектора по текущему кадру (статус, дистанция, высота и число точек объекта) показано крупно слева — оно приходит из плеера, на странице ничего не досчитывается. Пауза и сброс камеры — справа внизу, клавиши — ниже.
2. **Эталон организаторов**: сводка «N из 7» и «0 из 3», строка из десяти объектов (промахи помечены), разбор выбранного объекта. Полоса кадров и таблица всех объектов — во втором уровне. Для вопросов жюри полезны 4 и 10 (промахи), 6 (кратковременный СТОП).
3. **Дальность** и **Скорость обработки**: результаты с условиями измерений.
4. **Ложные тревоги** и **Устойчивость тревоги**: основные ограничения качества.
5. **Границы решения**, **Инженерные проверки**, **Источники данных**, **Реестр доказательств**: подробные ответы на вопросы.

## Управление 3D-сценой

Одинаково в главной сцене и в полном плеере. Клавиши работают, только когда сцена в фокусе: по клику по ней. Подсказка в углу сцены меняется, когда фокус получен; при потере фокуса движение сразу прекращается.

| | |
| --- | --- |
| WASD | лететь вперёд/назад/вбок |
| Q, E | вниз, вверх |
| Shift | втрое быстрее |
| R, «Сброс камеры» | вернуть исходный вид |
| мышь, колесо | вращение, масштаб |

Клавиши определяются по коду физической клавиши, поэтому на русской раскладке это те же ЦФЫВ. Вне сцены WASD не перехватываются: прокрутка и ввод на странице работают как обычно.

«Режим защиты» убирает боковую панель. Переключение — кнопками внизу, стрелками ←/→ или PageUp/PageDown. Escape возвращает обычный режим. Обычная прокрутка и управление 3D-сценой сохраняются. Это режим компоновки, а не полноэкранный режим браузера.

## Пересборка

Из корня репозитория:

```sh
venv/bin/python tools/dashboard.py
```

Главная использует `demo_template.html`. Для пересборки плеера: `venv/bin/python tools/demo.py` (в наборе должен быть `doubleT_obstacle`). `tools/dashboard.py --no-scene` пересобирает метрики без повторного расчёта статического кадра; фоновый плеер остаётся отдельным файлом.

Редактируется `gui/template.html`, затем пересобирается `gui/dashboard.html`. Генератор берёт данные из `runs/`, затем из `reference/`; методика выбора файлов остаётся в `tools/dashboard.py`. README не является источником чисел для интерфейса. Поэтому метрики README и конкретного локального прогона могут различаться: сверяйте раздел «Источники данных».

Полоса выбранного тестового объекта сопоставляет его истинную дистанцию с ближайшим решением кадра (±5 м). Показатель устойчивости рассчитывается отдельно по всем обнаруженным объектам, от первого СТОП до последнего обнаружения и до проезда окна объекта. Полоса не является временным рядом этого показателя.

Встроенный режим плеера: `demo.html?embed=1&clip=doubleT_obstacle&loop=1&start=10&end=68`. В этом режиме показываются только подтверждённые объекты и без заливки корпуса: рамка габарита, ореол и подпись с дистанцией не перекрывают точки силуэта. Ярче прочих — самый высокий подтверждённый объект рядом с ближайшим: у рельса на тех же 56 м стоит и предмет 0,2 м, и человек. Кандидаты, шкала дистанций и панель диагностики остаются в полном плеере. При открытии разделов dashboard фоновое воспроизведение приостанавливается; если зритель сам двигал камеру, на повторе она больше не отскакивает.
